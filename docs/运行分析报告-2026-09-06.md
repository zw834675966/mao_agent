## 3. 运行链路（代码事实）

数据流与 `CONTEXT.md` 一致，源码未另开 `--mode graph`：

```
corpus/*.md
    │ ingest
    ▼
data/vector_store.bin + data/tantivy_index/    [可选 ingest-graph → graph_store.bin]
    │ search / ask / serve / eval-retrieval
    ▼
hybrid: Vector + BM25 RRF（fuse 权重不变）
    │ 可选 1–2 hop DiGraph → union_graph_bonus（rrf_score=0，帽 8，无 rerank 时留 2 个尾槽）
    ▼
可选 Cohere rerank → LlmClient（失败/无 key → 离线四阶段模板）→ CitationVerifier
```

子命令（`src/cli/mod.rs`）：`init-samples` · `ingest` · `ingest-graph` · `search` · `stats` · `ask` · `serve` · `eval-retrieval`。

Embedder（`src/main.rs` `get_embedder` + `src/vector/embedder/mod.rs` `resolve_embedder`）：

1. `--offline` → `DeterministicEmbedder`（无 `.embedcache`）
2. 否则 `--embed-provider` 优先；未指定则 **Gemini key 先于 SiliconFlow key**
3. Gemini 768 / SiliconFlow bge-m3 1024 / Cohere embed-v4.0 1536 / FastEmbed 512
4. 无 key 且非 offline → 硬错误，不静默 hash

Serve 路由（`src/server/mod.rs`）：`/live` `/health` `/metrics` `/api/v1/{live,health,stats,metrics,search,ask,ask/stream,verify}`。`/health` 空索引 503（ADR 0002）。

**文档缺口（不是代码矛盾）**：`AGENTS.md` 仍写「Gemini → Cohere → FastEmbed」和「126 tests」。代码已有 SiliconFlow；测试实数 **130**。

## 5. 主要矛盾（运行面）

### P0 · `--offline` 维数被 Gemini 配置污染

`resolve_embed_dimension_with_provider` 在 `offline=true` 且 **没有** `explicit` 时返回 `LOCAL_EMBEDDING_DIM`（512）。但 `get_embedder`（`src/main.rs` 约 186–253 行）在 `--offline` 时仍：

1. 因 `config.toml [gemini]` 有 key，把 `provider` 自动设成 `gemini`
2. 把 `explicit_dim` 设成 `config_gemini_dimension()` → **768**
3. explicit 优先于 offline 默认 → `DeterministicEmbedder(768)`

后果：

- 默认样本库若是 768-hash，裸 `--offline`「看起来正常」，其实已经不是文档里的 512
- `data/offline_run2`（今早全量、512）被 identity guard **正确拒绝**
- `ingest_run.log` 里「offline 768-dim / 8074 chunks」是同一泄漏，不是 Deterministic 默认改成了 768

工作区绕过（不改代码）：

```bash
# 读全量离线库
cargo run --no-default-features -- stats --offline --embed-dim 512 \
  --index-file data/offline_run2/vector_store.bin

cargo run --no-default-features -- search --offline --embed-dim 512 --no-rerank \
  --index-file data/offline_run2/vector_store.bin \
  --tantivy-dir data/offline_run2/tantivy_index \
  "主要矛盾"
```

代码层修复方向（本报告不改生产代码）：offline 分支应忽略 provider/config 维数，或 identity 比对前强制 `LOCAL_EMBEDDING_DIM`。

### P1 · 默认索引已不是全量库

今早断点稿写：默认 `data/vector_store.bin` 是 Gemini 768 全量、未改动。现在默认是 **15 篇样本 / 59 块 / hash-768**。全量离线在 `offline_run2`。`ingest_run.log` 中途停在 8074 chunks，默认路径没有留下那次全量结果。

对 `search`/`ask`/`serve` 不传 `--index-file` 的人，实际打的是样本，不是 668 篇语料。

### P1 · 图谱未编译进默认运行

`src/graph/*` 已接线：`union_graph_bonus`、`HybridSearchResult.graph_paths`、ask/serve 同路径。缺 `data/graph_store.bin` 时 `try_load_graph` 静默 dual-only（设计如此，`evals/retrieval/GRAPH.md`）。

编译：

```bash
cargo run --no-default-features -- ingest-graph \
  --input evals/graph/golden_graph.json \
  --output data/graph_store.bin
```

### P2 · BM25 长查询 AND 零召回（今早已定位，代码仍在）

`src/index/fulltext.rs` 使用 Tantivy `QueryParser` 默认 **AND**。口语长句 hybrid 的 BM25 路可空，退化为向量单路。`eval-retrieval` 对金标用引号茎，所以 BASELINE 的 BM25 0.781 不能证明 search CLI 长句也绿。

### P2 · 摄取中断与 Tantivy PermissionDenied

今早 `offline_run/` 残留段文件导致重试 OS error 5。`ingest_run.log` 再次截断。运行手册应写：失败后换目录或清段，不要原地续写。

## 6. 和建议操作顺序

当前机器上要把「全量 + 图谱」跑起来，不必重 ingest：

```bash
# 1. 测试门（已绿，回归时再跑）
cargo test --no-default-features

# 2. 编译 golden graph
cargo run --no-default-features -- ingest-graph \
  --input evals/graph/golden_graph.json --output data/graph_store.bin

# 3. 对着全量 512 库检索（必须钉维）
cargo run --no-default-features -- search --offline --embed-dim 512 --no-rerank \
  --index-file data/offline_run2/vector_store.bin \
  --tantivy-dir data/offline_run2/tantivy_index \
  --graph-file data/graph_store.bin \
  "主要矛盾"

# 4. 服务（若要探活）：同样钉 512 + offline_run2 路径，bind 127.0.0.1
```

不要对默认 `data/vector_store.bin` 做「全量质量」判断。不要无 `--embed-dim 512` 去打开 `offline_run2`。
