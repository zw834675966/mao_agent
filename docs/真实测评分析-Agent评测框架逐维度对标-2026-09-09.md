> 方法声明：本文不做纸面推演。每个结论都标注证据来源：`path`（源码/文档定位）或 `command`（本机实测命令与原始输出）。无法测的维度明确标注"无证据，存疑"，不编造水位。

## 0. 项目形态判定（决定哪些维度适用）

mao_agent 不是多步工具编排 Agent（非 LangGraph/AutoGen 式的 Plan→Act→Observe 循环），而是**单请求 RAG 管线 + 双协议服务壳**：

| 形态 | 证据 |
|------|------|
| 检索→合成→验证 三段固定管线，单轮完成 | `src/agent/engine.rs:150-250`（`ask()` 内 1 次检索 + 1 次生成 + 引文核验，无迭代规划循环） |
| 无自主工具选择：运行期工具面固定 2 个 MCP 工具 | `src/mcp/tools/`（`query_dialectical_principles` / `verify_historical_citation`，`tools/list` 实测确认） |
| 自愈靠基础设施层（重试/回退），不靠 Agent 改写策略 | `src/retry.rs`（有界退避）、`src/agent/llm.rs`（在线→离线 fallback） |
| 已有离线可复跑的检索评测集 + 硬指标守护测试 | `evals/retrieval/`（105 易 + 26 难 gold queries）、`tests/retrieval_hard_eval_test.rs` |

这个判定直接决定：框架里"工具选择错误率、死循环拦截率、多轮上下文遗忘"等维度在 mao_agent 上**结构性不存在**（没有自由工具循环），应置换为**等价物**（检索错误率、失败终止保证、跨轮服务状态）——详见各节。

## 1. 维度一：端到端完成率 (Task Success Rate) — 部分可测，已实测

### 1.1 Pass@1 等价物：检索端到端指标（本次实测）

`command`: `cargo run --no-default-features --quiet -- eval-retrieval --k 5 --mode hybrid --no-rerank --offline --json`（2026-09-09 实测复跑）

| 查询集 | n | Recall@5 | MRR@5 | NDCG@5 | 对照框架及格线（Pass@1 ≥ 75%） |
|--------|---|----------|-------|--------|-------------------------------|
| 易集 `evals/retrieval/queries.jsonl` | 105 | **1.000** | 0.989 | 0.992 | 通过，但**无效水位**（见 1.2） |
| 难集 `evals/retrieval/queries_hard.jsonl` | 26 | **0.731** | 0.622 | 0.650 | Recall 0.73 略低于 75% 线；MRR 0.62 意味着约 1/3 查询的正确答案不在前位 |

难点实测样例（原始输出摘录）：paraphrase/cross_doc 类查询多在 top-5 内命中但排位靠后（MRR 0.33）；`hard_negative` 类两例完全 miss（Recall 0.0，gold 是哲学原著章节，检索器被同名衍生文献拉走）。

### 1.2 易集 1.0 是度量假象（项目自身文档已承认）

`path`: `evals/retrieval/BASELINE.md:21-29` — gold 查询由 chunk 原文模板化生成，词面重叠天然饱和，"not a meaningful ranking quality signal"。README 人检 5 例也注明 stem 来自原文。

**结论**：评估这个项目的 Task Success Rate 应以**难集为口径**：Recall@5=0.73 踩线、MRR@5=0.62 未达"答案排第一"的主流水位。这是当前最真实的一次"端到端完成率"。

### 1.3 Pass@k 稳定性：抓到一个真实反例（本日实测）

连续 3 次运行 `cargo test --no-default-features`（本日）：

| 次数 | 结果 | 失败点 |
|------|------|--------|
| 第 1 次 | 128 passed / **1 failed** | `vector::index::tests::test_vector_index_crud_and_search` panic at `src/vector/index.rs:924` |
| 第 2 次 | 128 passed / **1 failed** | 同上 |
| 第 3 次 | 128 passed / **1 failed** | 同上 |
| 对照：C11 终验报告（同 HEAD） | **209 passed / 0 failed** | `docs/C阶段终验报告-2026-09-09.md` §1.3 |

同码不同果 = 调度相关的不稳定。根因已定位（机制证据）：

- `HNSW_THRESHOLD_OVERRIDE` 是**进程全局原子**（`src/vector/index.rs:20`），测试可把它改成 2/50 等小值；
- `HNSW_THRESHOLD_TEST_LOCK`（`src/vector/index.rs:864`）只被 `test_hnsw_activates_at_threshold`、`snapshot_clone_does_not_rebuild_hnsw` 等**写方测试**持有（`src/vector/index.rs:942, 1002`——后者把阈值改成 2 后全程持锁跑）；
- `test_vector_index_crud_and_search`（断言 `!has_hnsw()`）**不拿锁**，插入第 2 个向量时若并发读到被改小的阈值 2（2 ≥ 2），HNSW 提前激活 → 断言必挂；
- 提交 `9b2e822`（"serialize HNSW threshold override across parallel tests"）修了写方向自己人打架，flake **转移**到了读方向的邻居测试。C11 报告的 209 全绿属于线程调度运气，不是稳定态。

这正是框架说的"单次看似成功，多跑几次断崖下跌"——发生在了**测试基础设施**上。修复方向（一行级）：`test_vector_index_crud_and_search` 同样持有 `HNSW_THRESHOLD_TEST_LOCK` 并先 `reset_hnsw_threshold_for_test()`；或将 override 从全局原子改为 per-index 字段注入。本次分析未改代码（见 §7 范围声明）。

### 1.4 生成侧 Pass@1：不可测，明确声明

`ask` 的 LLM 合成质量（Cohere command-r7b 在线 / 离线模板）没有任何量化基准：`evals/` 下只有检索 gold，没有问答 gold；`src/eval/` 只有 Recall/MRR/NDCG 三函数（`src/eval/mod.rs:1-9`）。离线模板四阶段结构有测试钉住（`src/agent/engine.rs:320-350`），但那测的是模板，不是推理质量。**此水位：无证据，存疑。**

## 2. 维度二：轨迹合规度 (Trajectory Fidelity) — 等价物已实测，水位好

mao_agent 无自由工具选择，等价指标置换为：**输入校验合规率 + 幻觉引文拦截率**。

### 2.1 工具调用参数合规（MCP stdio 实测探针，2026-09-09）

`command`: 6 条 JSON-RPC 经 stdio 打入 `cargo run -- mcp --offline`（initialize / tools/list / 正常核验 / 空参数 / 未知工具 / 捏造引文+不存在篇名）：

| 探针 | 实测响应 | 合规判定 |
|------|---------|---------|
| initialize | `protocolVersion 2024-11-05` + capabilities 正常回显 | ✅ 协议合规 |
| tools/list | 2 个工具，均带完整 `inputSchema`（required/enum/minimum/maximum 齐全） | ✅ Schema 自描述，客户端可静态校验 |
| 真引文《论持久战》 | `verdict: ExactMatch, confidence 1.0, matched_chunk_id doc_021ce9c4d7271db1_chunk_0002` | ✅ |
| 空参数 quote | JSON-RPC `-32602 "quote must not be empty"` | ✅ 拒绝，无幻觉执行 |
| 未知工具 `nonexistent_tool` | `isError: true` + 文本说明，**不 crash 不瞎编** | ✅ |
| 捏造引文 + 不存在书名 | `DocNotFound, confidence 0.0, is_valid: false`，且 `context_chunks` 兼容字段被明确忽略（反自我背书） | ✅ |

对照框架"参数 Schema 错误率接近 0%"：**服务端方向的合规是满格的**（拒绝非法输入、不虚构工具行为）。长度上限（quote 4000 / title 200 字符）在 `src/mcp/tools/citation.rs:10-11` 硬编码并有守卫。

### 2.2 幻觉引文拦截率：100%（守护测试钉死）

`path`: `src/agent/verifier.rs:259-347` — 对抗测试套件要求 **6/6 = 100% 拒绝**：近义替换（兵民→军民）、语序颠倒×2、生造词、跨篇拼接、随机噪声。匹配策略分级（精确子串→等长滑窗 Jaro-Winkler ≥0.85 且 Levenshtein 预算 0/1 编辑），短引文强制零编辑。这条与框架"参数错误率→0"的精神同构：**宁错杀不放过**，且测试断言写死了 100% 这个水位（`assert_eq!(reject_count as f32 / adversarial.len() as f32, 1.0)`）。

跨文档混淆用三重防御：标题过滤（`store.chunks_matching_title`）+ 归一化精确匹配 + claimed_title 与命中 chunk 的交叉告警（`src/agent/verifier.rs:92-110`）。

## 3. 维度三：执行步数与效率 (Step Efficiency) — 结构性优势 + 一个真实缺口

### 3.1 冗余与死循环：结构性免疫，但有形式化边界

- **冗余工具调用**：单请求管线无多步调用，冗余率=0（结构性，不是调出来的）。
- **死循环**：无自主循环体；唯一的"重试"在 HTTP 层且有界：`RetryPolicy::cohere_http()` 3 次封顶 / `embeddings_http()` 5 次封顶（`src/retry.rs:28-50`），backoff 指数增长封顶 2s/15s，`max_attempts=0` 有防 panic 兜底测试（`src/retry.rs:224-284`）。**"100% 主动跳出死循环"在形式上成立**：重试预算静态有界，不存在无界 while。
- 边界声明：`should_retry_status` 只重试 429/5xx（`src/retry.rs:57-59`），404/4xx 直接 fatal —— 这对幂等 GET 正确，对偶发写竞争偏保守，但方向是"少耗 token"。

### 3.2 真实缺口：无步级/轮次级观测

框架要求"捕获完整执行轨迹 (Plan→Thought→Action→Obs)"。mao_agent 的可观测边界：

- `tracing` 结构化日志（检索、重试、fallback 均有 `warn!/info!` 打点，`src/agent/llm.rs:118-124`、`src/retry.rs:118-124`）；
- `/metrics` 有 route 级 requests/errors/latency（见 §6.2）；
- **没有 span 树**（无 OpenTelemetry / Langfuse 语义），`ask` 内部"检索→prompt 组装→生成→核验"四步只有一个总时延，无法回答"卡在哪一步"。
- 缓解因素：`AgentAnswer` 结构体把中间产物（retrieved_chunks / citation_reports / rerank_scores）**作为数据返回**（`src/agent/engine.rs:20-36`），SSE 流也逐事件外吐（`retrieved → reranked → delta → citation → done`）——离线可回放，在线可旁路观测。属于"数据自描述"式半程 tracing。

## 4. 维度四：错误自愈率 (Self-Correction Rate) — 基础设施层自愈已实测钉死

框架口径"404/500 后换策略"在 mao_agent 的等价物是**分层降级链**，全部有测试证据：

| 故障注入 | 自愈行为 | 证据 |
|---------|---------|------|
| LLM API 500（wiremock 注入） | 3 次退避重试 → 整体降级到离线辩证模板，答案仍含检索证据与四阶段结构 | 测试 `test_llm_api_error_falls_back_offline`（`src/agent/engine.rs:388-387` 区段，断言 API error + key 存在时必须回退离线模板） |
| 重试仍失败 | fallback 计数器 `mao_llm_fallback_total` 上报 | `src/server/metrics.rs:33` + `fallback_counter` 注入链（`src/agent/engine.rs:98-118`） |
| Tantivy json_chunk 损坏/为空 | 从 stored fields 就地重构 chunk，不丢命中不 panic | `src/index/fulltext.rs:378-410`（C10 修复，含单测） |
| 图快照损坏 vs 缺失 | 缺失→优雅无图降级；存在但损坏→**硬失败拒绝静默降级** | `src/main.rs:393-412` + MAOGS01 魔数校验（`src/graph/store.rs:28,83-134`） |
| 索引维度不匹配 | 明确报错并给出操作提示（今天实测复现：512 快照 vs 在线 1024 请求 → 拒绝执行 + 提示 `ingest --offline` 重建） | 本日 §3.2 MCP 探针 stderr 输出原文 |
| 429/5xx/网络错误 | 指数退避 + jitter，3~5 次有界 | `src/retry.rs`（全套单测） |

对照"修正完成率 ≥ 60%"：**在已覆盖的故障类上，自愈路径 100% 有测试钉住**。但注意口径差：mao_agent 的自愈是**工程降级**（保证不崩、不幻觉、有诊断），不是**策略自愈**（Agent 理解报错语义后改写计划）——它没有"计划"可改。框架原义若指后者，则本维度 N/A，只有基础设施层达标。

## 5. 维度五：经济与时延 (Cost & Latency) — 半可测：有时延无 token 计量

### 5.1 实测时延（本机，冷启动含进程+索引加载）

`command`: `Measure-Command` 包裹 CLI（2026-09-09）：

| 操作 | 实测 |
|------|------|
| `ask --offline`（检索+模板合成+核验，59 chunk 索引） | **7.13 s**（冷启动主导；进程启动+fastembed 旁路+索引加载占大头） |
| `search --offline --no-rerank` | **2.55 s** |

服务态热路径另有 route 级观测：`GET /metrics` 暴露 search/ask/mcp 三路的 `latency_avg_ms / latency_max_ms / errors`（`src/server/metrics.rs:36-48`，实现 `record_*` 在 `:70-100`）。注意是 **avg+max 摘要，无分位数**（无 p95/p99），长尾不可见。

### 5.2 token 计量：结构性缺失（grep 全库无证据）

`grep -i "usage|token_count|prompt_tokens|completion_tokens" src/` → **0 命中**。在线 LLM 调用不回读 usage 字段，离线模板路径无 token 概念。对照框架"Token 消耗 ≤ 同类方案 1.2 倍"：**当前无法作答**。可估计的间接事实：离线路径 0 外呼、在线路径 prompt 由 `top_k` chunks 硬性封顶（MCP `top_k` ≤ 20），上下文预算可控；但"是否 1.2 倍内"没有数。

### 5.3 并发与成本护栏（已落地，加分项）

`--max-concurrent-asks` / `MAO_MAX_CONCURRENT_ASKS` 默认 32（AGENTS.md；由 ask 与 MCP `synthesize:true` 共用闸门），free-tier 批量节奏 100ms 停顿有测试钉住（`vector::store::tests::test_ingest_batch_pace_*` 3 条）。

## 6. 公开基准对照与自建流水线适配

### 6.1 公开基准：三项全不适配，应放弃对标

| 基准 | 适配判定 | 理由 |
|------|---------|------|
| SWE-bench Verified/Lite | ❌ | 评审对象是真实 GitHub issue 的代码改动；mao_agent 不生成代码、无沙箱执行回路 |
| GAIA / τ-bench | ❌（τ-bench 半沾边） | GAIA 要多模态文件读取+网络检索；τ-bench 的"多轮状态追踪+API 操作"形态最近似，但需要可写业务数据库环境，mao_agent 是只读知识库 |
| WebArena / OSWorld | ❌ | 无浏览器/OS 操控能力 |

这不是缺陷——mao_agent 是**垂直检索问答**型 Agent，公开基准没有覆盖"中文历史文献引文级 grounding"的现成集。框架第三节的判断在这里成立：**该走自建私有测评集路线**，而且项目已经走了一半（见 6.2）。
