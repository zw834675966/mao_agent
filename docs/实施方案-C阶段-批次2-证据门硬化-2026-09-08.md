#### 1. 任务背景与核心缺陷
- **现状缺陷定位**：[`src/vector/store.rs:260-272`](file:///D:/rust/mao_agent/src/vector/store.rs#L260-L272)
  ```rust

  ```
  而在 [`src/vector/persist.rs:17-21`](file:///D:/rust/mao_agent/src/vector/persist.rs#L17-L21) 中：
  ```rust

          bincode::serialize(identity).map_err(|e| VectorError::Serialization(e.to_string()))?;
      let index_bytes =
          bincode::serialize(index).map_err(|e| VectorError::Serialization(e.to_string()))?;
      ...
  ```
- **危害分析**：
  上一轮 C5 虽然将磁盘写入 `atomic_replace` 移出了锁作用域，但整表 `bincode::serialize(index)` 仍然在读锁持有期间执行！对于包含数千至数万维向量的索引表，bincode 的二进制序列化属于重度 CPU 密集型任务（耗时数十至数百毫秒）。在此期间，持有 `index.read().await` 读锁会直接阻塞任何需要获取写锁的操作（如 `index_chunks`、`clear`、动态更新等），形成写饥饿，与原设计方案 2.5 要求「序列化彻底移出锁外」存在残余差距。

- **涉及文件**：

     ```rust
         let snapshot = index_guard.snapshot_clone();
     ```

### 卡 C10：fulltext json_chunk 空/坏降级不丢命中 (Fallback Reconstruction)

#### 1. 任务背景与核心缺陷
- **现状缺陷定位**：[`src/index/fulltext.rs:378-397`](file:///D:/rust/mao_agent/src/index/fulltext.rs#L378-L397)
  ```rust
  let json_str = retrieved_doc
      .get_first(self.f_json_chunk)
      .and_then(|v| v.as_str())
      .unwrap_or_default();

  if let Ok(chunk) = serde_json::from_str::<DocumentChunk>(json_str) {
      // Check remaining predicate filters (tags, date range, etc.)
      if let Some(f) = filter
          && !f.matches(&chunk)
      {
          continue;
      }

      results.push(FullTextSearchResult {
          chunk_id,
          score,
          rank: rank + 1,
          chunk,
      });
  }
  ```
- **危害分析**：
  如果 `json_str` 缺失（为空字符串），或者由于字段变更、损坏导致 `serde_json::from_str` 解析失败，当前逻辑直接静默跳过（`results.push` 未执行），导致通过 BM25 算分本已成功命中的文档被凭空抹去。这直接破坏了检索召回率与系统容错韧性。

#### 2. 改造方案与精确改动点
- **涉及文件**：
  - 核心修改与测试：[`src/index/fulltext.rs`](file:///D:/rust/mao_agent/src/index/fulltext.rs)
- **代码重构细节**：
  当 `serde_json::from_str::<DocumentChunk>(json_str)` 解析失败时，不抛弃该 hit，而是利用 Tantivy Schema 中已单独持久化存储的独立字段进行优雅降级重构：
  ```rust
  let chunk = match serde_json::from_str::<DocumentChunk>(json_str) {
      Ok(c) => c,
      Err(err) => {
          tracing::warn!(
              chunk_id = %chunk_id,
              error = %err,
              "json_chunk missing or corrupted; falling back to reconstructed DocumentChunk from index fields"
          );
          let doc_id = retrieved_doc
  ```
