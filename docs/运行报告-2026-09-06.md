## 一、项目分析

`mao_agent` 是一个单体 Rust 项目（bin + lib），定位为**中文历史文献的高性能向量数据库与辩证认知推演引擎**。

### 架构分层

| 层 | 模块 | 职责 |
|---|---|---|
| 语料层 | `corpus` | Markdown 解析 / YAML Frontmatter / CJK 清洗 / 语义分块 |
| 向量层 | `vector` | 多 Embedder 链（Offline 确定性 hash → Gemini 768 维 → Cohere 1536 维 → FastEmbed 512 维）、快照存储、HNSW ANN |
| 索引层 | `index` | Tantivy BM25 倒排 + RRF 混合排序融合 |
| 图谱层 | `graph` | DiGraph 知识图谱 + 查询扩展（`data/graph_store.bin`，本次运行未启用） |
| 精排层 | `rerank` | Cohere rerank-v3.5，无 key / offline 自动降级 |
| 推理层 | `agent` | 四阶段唯物辩证法推演（调查研究→主要矛盾→理论综合→指导实践）+ 引文真子串核验 |
| 服务层 | `server` | Axum REST + SSE，request-id / metrics / CORS / 探活 |
| 评测层 | `eval` | Recall / MRR / NDCG@k |

### 语料规模

- Markdown 文献 **668 篇**（顶层经典 15 篇 + hacker_laws 240 + hello_algo 240 + papers_we_love 161 + awesome_scalability 12）
- 评测金标集 `evals/retrieval/queries.jsonl` 共 **105 条**查询

### BP0 · 编译
`cargo build --no-default-features` — ✅ 成功（1m06s，增量编译）

### BP1 · 索引状态检查（stats）
- 现有 `data/vector_store.bin` 由 **Gemini embedding-2（768 维）** 构建
- 当前 `config.toml` 仅配置了 Cohere 密钥 → 解析为 embed-v4.0（1536 维）
- ❌ **触发维数守卫报错**（预期行为）：模型不匹配被正确拦截，未产生脏数据
- 处置：不破坏原索引，改用 `--offline` 通道在独立目录重建

### BP2 · 离线摄取（ingest）
`ingest --offline --index-file data/offline_run2/...`

| 项 | 值 |
|---|---|
| 耗时 | 29m15s（第二次运行；首次 16m 时因 PermissionDenied 失败） |
| 解析 | 668 个文件发现，3 篇 hello_algo index.md 缺 `title` 字段解析失败，665 篇有效 |
| 分块 | 生成 5764 chunks → 持久化 **5372 唯一分块 / 528 文档 / 512 维 / 334.5 万字符** |
| 快照 | vector_store.bin 22,895,636 字节 |
| HNSW | 向量数越过 5000 阈值后自动激活，每批次日志可见 "HNSW graph rebuilt" |

- ⚠️ **首次摄取失败复盘**：第一次运行被超时 SIGTERM 中断后，残留半成品 Tantivy 段文件；第二次摄取复用同一目录时 Tantivy writer 写段文件报 `PermissionDenied (OS error 5)` 退出。**教训：摄取中断后必须清理/更换 Tantivy 目录再重试**。
- ✅ **5764 → 5372 差异已定位**：`VectorStore::insert_batch`（src/vector/index.rs:325）按 `chunk_id` 做 **upsert 幂等去重**，重复分块覆盖而非新增，非数据丢失。

### BP4 · 三模式检索（search）
查询 `"实践是检验真理的唯一标准"`（top-3）：

| 模式 | 结果 | 耗时 |
|---|---|---|
| hybrid | ✅ 3 条，Top1《人的正确思想是从哪里来的？》(1963)、Top2《改造我们的学习》(1941)，语义高度相关 | 36.5s（含索引加载+HNSW 重建） |
| vector | ✅ 3 条，与 hybrid 排序一致 | 36.0s |
| bm25 | ⚠️ **召回 0 条** | 0.8s |

- ⚠️ **发现 1（中危）· BM25 长查询零召回**：`"矛盾论"`（1 词）召回 2 条、英文 `"Fallacies of Distributed Computing"` 召回 2 条，但 9 词口语长查询召回 0。根因在 `src/index/fulltext.rs:211-218`：Tantivy `QueryParser` 将分词后各词按**交集（AND）语义**组合，长查询无任何文档同时包含全部分词 → 0 召回，导致 hybrid 中 BM25 路贡献为空（结果中 `BM25: N/A`），混合检索实际退化为向量单路。**建议**：改为 Should(OR) 组合或引入 minimum-should-match 逻辑。
- ⚠️ **发现 2（低）· 冷启动延迟**：search/ask 每次进程启动需 ~35s 加载快照并重建 HNSW 图（快照不持久化图，属文档化设计），对 CLI 单次调用可感知，服务模式无此问题。

## 三、结论与建议

### 总体结论
项目在离线通道下**全链路可运行**：摄取 → 检索 → 问答 → 评测 → 服务 7 个断点全部打通；维数守卫、引文核验、HNSW 自动激活、指标埋点等防护/观测机制均按设计工作。核心检索质量（离线基线）优异。

### 问题清单（按优先级）

| # | 级别 | 问题 | 位置 | 建议 |
|---|---|---|---|---|
| 1 | 中 | BM25 长查询 AND 语义零召回，hybrid 退化单路 | `src/index/fulltext.rs:211` | 改 OR / minimum-should-match |
| 2 | 中 | 摄取中断后残留段文件导致重试 PermissionDenied | Tantivy writer | 摄取启动前清理孤儿锁/临时段文件 |
| 3 | 低 | 现有 `data/vector_store.bin`(Gemini 768 维) 与当前 Cohere-only 配置不匹配，默认 `stats/search` 直接报错 | 配置解析 | 恢复 Gemini key 或用 Cohere 重新 ingest |
| 4 | 低 | 3 篇 hello_algo index.md 缺 `title` frontmatter 被跳过 | corpus 源文件 | 补 frontmatter |
| 5 | 低 | CLI 冷启动 ~35s（HNSW 重建） | 快照加载 | 如需优化可评估持久化 HNSW 快照 |
