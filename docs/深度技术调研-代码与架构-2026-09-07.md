# 深度技术调研：代码与架构实证分析

**项目**: mao_agent (Rust 向量数据库 + 检索 agent 引擎，中文历史语料)  
**日期**: 2026-09-07  
**调研范围**: 检索链路、检索质量、语料与分块、架构与技术债、构建健康度、测试资产

---

## 1. 执行摘要

1. **检索链路完整且正确**：Hybrid 模式（BM25+向量 RRF 融合→图扩展→rerank→top_k）完整可运行，但图扩展、混合检索管道在 4 个位置重复实现，存在显著发散风险。
2. **离线评测指标饱和但无区分力**：easy 105 查询集 Recall@5=1.0（Hybrid），因为金标查询通过模板生成，词法重合度极高；hard 26 查询集 Hybrid Recall@5=0.769 才是更有意义的排名信号，Vector 模式在硬查询上仅 0.538，暴露了确定性哈希嵌入在语义泛化上的根本局限。
3. **HNSW ANN 在标准评测集上无法激活**：评测语料仅 59 chunks（远低于 HNSW 阈值 5000），`--force-brute` 与默认模式完全一致；全量语料离线索引（5372 chunks）已激活 HNSW，合成回归测试（3000 向量，threshold=500）验证 mean_recall@5 ≥ 0.99。
4. **分块策略缺少句子边界感知**：分块器按段落边界 + 硬 600 字符切割，不对齐中文标点（`。！？`），超大段落可能在句子中间切断；CJK 清洗器移除标题内 CJK 字符间空格（如"第一章 矛盾论"→"第一章矛盾论"），存在语义可读性退化。
5. **架构层面：P0 无（无 crash/数据丢失），P1 有 4 项（代码重复、性能陷阱），P2 有 13 项（配置耦合、缺失的版本头、非恒定时间比较等）。**

## 3. 检索链路剖析

### 3.1 完整数据流

```
用户查询
  │
  ├─[1] 向量搜索 (VectorStore::search_with_force_brute)
  │     src/vector/store.rs:61-71 → src/vector/index.rs:408-453
  │     嵌入查询 → 归一化 → 若 HNSW 激活且非 force_brute:
  │       ANN: candidate_k = top_k*2*20, max(EF_SEARCH*2=400)
  │       ef = max(k, 200) → 重打分（精确点积）→ 不足则回退 brute
  │     否则: 精确暴力点积扫描（含倒排索引候选集裁剪）
  │     返回 top_k*2
  │
  ├─[2] BM25 搜索 (FullTextIndex::search)
  │     src/index/fulltext.rs:245-402
  │     口语化 CJK 查询: 预分词为 Should-union（BooleanQuery）
  │     否则退化到 Tantivy QueryParser
  │     合并 filter 子句（period/volume/category）→ 返回 top_k*2
  │
  ├─[3] RRF 融合 (HybridSearchCoordinator::fuse)
  │     src/index/hybrid.rs:52-108
  │     rrf_score = weight / (60 + rank)  (rank 1-indexed)
  │     vector_weight=0.5, bm25_weight=0.5
  │     按 chunk_id 合并 → 降序排序 → 截断 top_k*2
  │
  ├─[4] 图扩展 (GraphStore::expand + union_graph_bonus)
  │     src/graph/store.rs:123-195 → src/graph/expand.rs:54-128
  │     种子: Jieba 分词查询 → 匹配实体名/别名
  │     BFS 有向 2-hop（Outgoing 边）→ 解析 source_refs
  │     双路命中: 标注 graph_paths，保留 RRF 分数
  │     图独有: 最多 8 个 (GRAPH_BONUS_CAP)，rrf_score=0.0
  │     无 rerank: 保留 2 个尾部槽位 (GRAPH_RESERVED)
  │     有 rerank: 全量返回（rerank 后截断）
  │
  └─[5] Rerank (rerank_or_fallback)
        src/rerank/mod.rs:28-45
        若 CohereReranker 配置且未 skip:
          POST https://api.cohere.com/v2/rerank
          model: rerank-v3.5, top_n = top_k
          按 relevance_score 降序重排 → 截断 top_k
          失败: warn + 回退融合序
        若无 reranker: 直接截断 top_k（融合序）
```

### 3.3 技术债汇总：硬编码参数

HNSW 全部参数（M、ef_construction、ef_search、激活阈值、seed、候选集乘数）均为硬编码常量。对于需要针对不同语料规模调优的生产部署，这构成了显著的操作障碍。建议至少将 HNSW 参数暴露为配置项，并考虑将 `effective_hnsw_threshold()` 的测试覆盖机制推广为生产配置。

## 4. 检索质量实测数据

### 4.1 标准评测集（easy, 105 queries, k=5, offline 512-dim, no-rerank）

| 模式 | Recall@5 | MRR@5 | NDCG@5 |
|------|----------|-------|--------|
| **Hybrid** (BM25+Vector RRF) | **1.000** | **1.000** | **1.000** |
| Vector | 1.000 | 0.965 | 0.974 |
| BM25 | 1.000 | 0.995 | 0.996 |

**BASELINE 对照**（Cycle 12 addendum 2026-09-06）:

| 模式 | Recall@5 | MRR@5 | NDCG@5 |
|------|----------|-------|--------|
| Hybrid | 1.000 | 0.995 | 0.996 |
| Vector | 1.000 | 0.965 | 0.974 |
| BM25 | 1.000 | 0.995 | 0.996 |

**结论**: 实测与 BASELINE 基本一致。Hybrid 的 MRR/NDCG 从 0.995/0.996 提升至 1.000/1.000，差异在浮点精度范围内（可能因索引重建顺序微调）。**easy 评测集因词法重合度极高（auto-generated 模板），Recall@5 饱和，不具备语义排名区分力。**

### 4.2 硬查询集（hard, 26 queries, k=5, offline 512-dim, no-rerank）

| 模式 | Recall@5 | MRR@5 | NDCG@5 |
|------|----------|-------|--------|
| **Hybrid** | **0.769** | **0.573** | **0.621** |
| Vector | 0.538 | 0.407 | 0.441 |
| BM25 | 0.731 | 0.635 | 0.660 |

**关键发现**:
- **Hard 查询集才是有意义的排名信号**：easy 集 8-gram 包含率 Recall@5 ≥ 0.90（`tests/retrieval_hard_eval_test.rs:49`），hard 集 < 0.35（同上:114），且所有 hard 查询的 LCS < 8。
- **Hybrid 在 hard 上表现最优** (Recall@5=0.769)，验证了 RRF 融合的有效性。
- **Vector 在 hard 上最弱** (Recall@5=0.538)：确定性哈希嵌入（字符 n-gram）无法捕捉语义同义改写（paraphrase），在 hard 查询上暴露了根本局限。
- **BM25 在 hard 向量上表现意外强劲** (Recall@5=0.731 > 0.538)：Jieba 分词 + 领域词汇注入 + 口语化查询 Should-union 修复（Cycle 12）对中文 paraphrase 有较好的词法匹配能力。

### 4.3 Force-Brute vs ANN 对比

| 模式 | 指标 | 默认 | force-brute |
|------|------|------|-------------|
| Hybrid | Recall@5 | 1.000 | 1.000 |
| Hybrid | MRR@5 | 1.000 | 1.000 |
| Vector | Recall@5 | 1.000 | 1.000 |
| Vector | MRR@5 | 0.965 | 0.965 |

**结果完全一致**——因为评测语料仅 59 chunks，远低于 HNSW 激活阈值（5000），两种模式均走精确暴力扫描路径。**在标准评测集上无法测量 ANN 近似带来的召回损失。**

### 4.4 ANN 召回损失的实际量化

**合成回归测试** (`tests/hnsw_regression_test.rs`):
- 3000 个 64-dim 单位向量，50 个查询，threshold override=500
- 结果: `mean_recall@5 ≥ 0.99`（|delta| < 0.01）
- 此测试验证了 HNSW 实现的基本正确性

**全量语料离线索引**: 5372 chunks（已激活 HNSW），但 gold queries 仅覆盖 15 篇样本文献，评测结果会受全量语料中无关文档的干扰。未对全量语料执行 ANN vs brute-force 对比评测（留待后续）。

### 4.5 关于"确定性哈希嵌入不代表真实语义"的明确说明

本次评测使用的 `DeterministicEmbedder`（512-dim 字符 n-gram 哈希）**仅验证链路正确性，不代表真实语义召回质量**。其特性：
- 相同文本 → 相同向量（确定性）
- 同义词/改写 → 向量可能不相似（无语义泛化）
- 评测中 easy 集 Recall=1.0 是因为查询模板直接内嵌了 chunk 原文（`「...」`引用），哈希嵌入自然匹配
- 真实语义检索需使用 BAAI/bge-m3 (1024-dim) 或类似语义嵌入模型

### 5.2 CJK 清洗规则 (`src/corpus/cleaner.rs`)

**流程** (`clean_cjk_spaces`, 第 22-55 行):
1. 全角空格 `　` 和 NBSP ` ` → ASCII 空格（第 27 行）
2. 数字间空格压缩（迭代不动点）: `"1 9 4 9"` → `"1949"`（第 30-36 行）
3. CJK 字符间空格移除（迭代不动点）: `"毛 泽 东"` → `"毛泽东"`（第 39-45 行）
4. 数字-CJK 和 CJK-数字空格清理: `"1949 年"` / `"第 3"`（第 48-49 行）
5. 多换行符规范化: `\n{3,}` → `\n\n`（第 52 行）

### 5.3 分块策略 (`src/corpus/chunker.rs`)

| 参数 | ingest 值 | 默认值 | 位置 |
|------|-----------|--------|------|
| max_chars | 600 | 600 | `chunker.rs:20` |
| min_chars | 100 | 120 | `main.rs:310` / `chunker.rs:21` |
| overlap_chars | 50 | 60 | `main.rs:311` / `chunker.rs:22` |
| inject_context_header | true | true | `chunker.rs:23` |

**算法** (`chunk_document`, 第 39-145 行):
1. 段落提取: 按 markdown 标题（`#`）和空行边界分割
2. 超大段落强制分割: 任何超过 max_chars 的段落按字符数组硬切割（防止远程嵌入 API 400 错误）
3. 缓冲区累积: 段落按序追加，超过 max_chars 或节标题变化时刷新
4. 重叠: 仅限同节内，使用字形（grapheme）聚类提取最后 overlap_chars 个字形
5. 面包屑导航: `【文献】《标题》（日期 · 时期 · 卷册）\n【章节】路径\n【正文】...`

### 5.4 分块策略对中文历史文本的适配问题

| 问题 | 严重度 | 说明 |
|------|--------|------|
| **无句子边界对齐** | 中 | 分块器不检测 `。！？` 等标点，按段落边界或硬 600 字符切割。段落超过 600 字符时可能在句子中间断开。 |
| **标题文本空格移除** | 中 | `clean_cjk_spaces` 移除 CJK 字符间所有空格，包括标题文本中的 `"第一章 矛盾论"` → `"第一章矛盾论"`（`src/corpus/cleaner.rs:69-72` 测试确认）。对中文母语读者可读性下降。 |
| **短节跨边界合并** | 低 | 当上一节缓冲区 < min_chars 时，不会因节标题变化而触发刷新，导致短节与下一节内容合并（`chunker.rs:65-69`）。 |
| **无表格处理** | 低 | 语料中无表格，但流水线无表格解析/处理代码。若将来添加表格，表格行将被视为普通文本行，可能被拆分到不同 chunk。 |
| **无句内注处理** | 低 | `extract_footnotes` 仅处理行级脚注标记（`[1]`、`〔1〕`）和 `# 注释` 节，不处理括号内联注释（如 `（参见《实践论》）`）。 |
| **无 `\r` 处理** | 低 | `clean_cjk_spaces` 概念上不处理 `\r`，但 `std::fs::read_to_string` 在 Windows 上规范化 `\r\n` → `\n`。来自其他来源的文本可能保留 `\r`。 |

### 6.3 持久化方案分析

| 组件 | 格式 | 版本 | 维度检查 | 损坏恢复 |
|------|------|------|----------|----------|
| 向量快照 | bincode + MAGIC(`MAOVS01\0`) + identity | ✅ 有魔数，无独立版本字段 | ✅ IdentityMismatch/DimensionMismatch | ✅ 截断头检测，原子替换防撕裂 |
| Tantivy 索引 | MmapDirectory | Tantivy 原生格式 | N/A | ❌ 无显式恢复，损坏→回退纯向量 |
| 图快照 | bincode (无头) | ❌ 无魔数/版本 | ❌ 无 | ❌ 仅 bincode 反序列化失败检测 |
| Embed cache | bincode + header | ✅ model/dimension 头 | ✅ 不匹配则丢弃重建 | ✅ 损坏则丢弃重建 |

**主要风险**: `graph_store.bin` 无任何身份校验。一个错误的或过时的图文件仅在 bincode 反序列化时失败，`try_load_graph` 静默降级为 dual-only 检索，掩盖了配置错误。建议添加与向量快照一致的 MAGIC + identity 头。
