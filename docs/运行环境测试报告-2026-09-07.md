## 5. 问题清单

1. **上一轮主进程在等编译时回合耗尽**，构建其实还在跑。本轮用 PID + `Finished` 续上，没有重编。以后对 CM4 上的 release 构建应按 20–40 分钟估，不要按桌面 x86 的几分钟估。
2. **PowerShell 会展开 `$?`、`$PID` 等**。本轮判断成败只用日志 `Finished` / `BUILD_EXIT=True` 和远端 bash 脚本，避免把本地自动变量打进 SSH。
3. **登录 shell 无 cargo**：裸 `rustc` 报 `command not found`。所有远端命令必须 `source /home/ems/.cargo/env`。
4. **`data/graph_store.bin` 不存在**：hybrid 静默 dual-only。要图谱扩展需另跑 `python scripts/build_knowledge_graph.py` + `ingest-graph`（本轮未做）。
5. **`--offline` 确定性 512 维哈希**：功能冒烟够用，语义召回不够。本次 search Rank 5 打到 hello-algo，就是哈希碰撞/无关高分，不是语料错误。
6. **HNSW 未启用**：阈值 ≥5000 向量，本库 4860，走精确扫描。817 ms hybrid 对 CM4 可接受；库再涨会更明显。
7. **ingest 文档数 447 vs 汇总 443**：无错误日志，按唯一 `doc_id` 解释得通，但 CLI 没有打印那 4 篇去向，排障不方便。
8. **`init-samples` 写进已有大语料目录**：15 篇示例和多域 corpus 混在一起 ingest。冒烟能过；若要「纯样本」应用单独 `--corpus-dir`。
9. **未测默认 feature `local-embed`**：CM4 上编 FastEmbed/ONNX 更重，且首次要下模型。本轮按 `--no-default-features` 验收离线路径。
10. **target 必须放 SSD**：SD 根盘只剩 8.8 G，target 已 953 MiB。继续 debug+release 双 profile 或打开 `local-embed` 时更要盯盘。
11. **本轮测试带了 `--release`**：与用户字面命令不完全一致，理由见上。debug 测试在此机等于第二次全量编译。

## 6. 结论与建议

**结论**：`ems` 这台 CM4 可以作为 mao_agent 的 **aarch64 离线运行环境**。Rust 1.98.0 + edition 2024 能编过；165 测试全过；init/ingest/search/serve 探活闭环成立。适合做 CI 以外的 ARM 回归机，或内网 `--offline` 演示。

**建议**：

1. 继续把 `CARGO_TARGET_DIR` 钉在 `/mnt/ssd/...`，并在文档/脚本里写死 `source ~/.cargo/env`。
2. 生产或要可引用的检索，不要用哈希嵌入。CM4 上优先 SiliconFlow `BAAI/bge-m3`（需 API），或评估是否值得在 ARM 上开 `local-embed`（ONNX + 内存）。
3. 若要完整 hybrid：补 `ingest-graph`；向量过 5000 后再看 HNSW 是否真降延迟。
4. 长期跑 `serve` 时绑非 22 端口（18080 已验证空闲），默认回环即可；出网段再加 `--api-token`（ADR 0005）。
5. 以后在 Windows 工作站 SSH 到这台机，脚本放到远端 bash 执行，不要让 PowerShell 插值 `$?`。
