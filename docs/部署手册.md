# mao_agent 部署手册

> 基于仓库实际 CLI（`src/cli/mod.rs`）、配置（`config.example.toml` / `src/config.rs`）、健康检查 ADR（`docs/adr/0002`–`0005`）与运维 runbook（`docs/ops/runbook.md`）整理。  
> 面向 Linux 服务器上的 B 级内网部署；默认绑定回环，非环回需显式鉴权。

---

## 1. Linux 服务器最低运行要求

| 项目 | 要求 | 说明 |
|------|------|------|
| OS | 常见 x86_64 Linux（CI 使用 `ubuntu-latest`） | 无特殊发行版锁定 |
| Rust | **stable** 工具链，支持 **edition = "2024"** | 见 `Cargo.toml`；CI：`dtolnay/rust-toolchain@stable` |
| CPU / 内存 | ≥ 2 核 / ≥ 2 GiB 建议 | 索引加载与 ask SSE 并发会占内存；ask 默认并发上限 32 |
| 磁盘 | 语料 + `data/vector_store.bin` + `data/tantivy_index/` + 可选 `data/graph_store.bin` | 开启默认 feature `local-embed` 时另需 ONNX 模型缓存（首次下载） |
| 网络 | 可选 | `--offline` 可无外网嵌入；生产 SiliconFlow / Gemini / Cohere 需出站 HTTPS |
| 编译依赖 | `build-essential`（gcc/g++/make）、`pkg-config`、`curl`/`git` | `cargo build` 编译原生依赖所需；**不要**假设只需拷贝源码即可运行未编译二进制 |

**运行时路径约定（相对工作目录）：**

- 向量快照：`data/vector_store.bin`（`--index-file`）
- Tantivy：`data/tantivy_index/`（`--tantivy-dir`）
- 可选图谱：`data/graph_store.bin`（`--graph-file`；缺失为 no-op）
- 配置：`config.toml` 或环境变量 `MAO_AGENT_CONFIG` 指向的文件

## 2. 依赖安装与编译

### 2.1 系统包（Debian/Ubuntu 示例）

```bash
sudo apt-get update
sudo apt-get install -y build-essential pkg-config curl git
# 安装 rustup + stable（若尚未安装）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
rustup default stable
```

### 2.2 配置

```bash
cp config.example.toml config.toml
# 生产嵌入：填写 [siliconflow].api_key（BAAI/bge-m3，1024 维）
# 可选：[cohere] 仅 chat / rerank；[gemini] 可选 768 维嵌入
# 可选：[server] cors_origins / api_token / max_concurrent_asks
# 密钥优先用环境变量，勿提交 config.toml
```

常用环境变量：

| 用途 | CLI | Env |
|------|-----|-----|
| SiliconFlow 嵌入密钥 | `--embed-api-key` | `SILICONFLOW_API_KEY`（另有 `EMBED_API_KEY`） |
| Gemini 嵌入密钥 | `--gemini-api-key` | `GEMINI_API_KEY` |
| Cohere chat/rerank | `--api-key` | `COHERE_API_KEY` |
| CORS 白名单 | `--cors-origins` | `MAO_CORS_ORIGINS` |
| API Bearer | `--api-token` | `MAO_API_TOKEN` |
| ask 并发 | `--max-concurrent-asks` | `MAO_MAX_CONCURRENT_ASKS`（默认 32） |
| 配置文件路径 | — | `MAO_AGENT_CONFIG` |

### 2.3 推荐编译方式

```bash
# 日常 / CI / 服务器：不拉 fastembed/ONNX（与 CI release-build 一致）
cargo build --release --no-default-features

# 需要本机 FastEmbed（默认 feature local-embed）时再开默认 features
cargo build --release
```

冒烟索引（确定性离线嵌入，512 维）：

```bash
cargo run --no-default-features -- init-samples
cargo run --no-default-features -- ingest --offline --corpus-dir corpus --batch-size 32
cargo run --no-default-features -- serve --offline --bind 127.0.0.1:3000
```

生产 SiliconFlow（须与检索端同一后端；1024 维）：

```bash
cargo run --no-default-features -- ingest --embed-provider siliconflow --batch-size 16
# 远程批次 CLI 间隔约 100ms；建议 batch-size 16~32（默认 32）
```

## 3. `--no-default-features` 与 `--offline`：区别与场景

二者**不是一回事**，可组合使用。

| | `cargo … --no-default-features` | CLI `--offline` |
|--|--------------------------------|-----------------|
| 层级 | **Cargo feature**：关闭默认 `local-embed`（不编译/不链接 `fastembed`） | **运行时参数**：选用确定性 hash 嵌入器 |
| 作用 | 减小依赖树、加快编译、避免首次下载 ONNX 模型；适合 CI/服务器 | 嵌入不走网络；维度默认 **512**（可用 `--embed-dim` 覆盖）；hybrid 会跳过 Cohere rerank |
| 无密钥时 | 若未传 `--offline` 且无 SiliconFlow/Gemini/Cohere 密钥 → **硬错误**（无静默 hash 回退） | 明确走 DeterministicEmbedder |
| 典型场景 | 生产二进制、CI `clippy`/`test`/`release-build` | 本地冒烟、无网验收、与 `--offline` ingest 配对的 search/ask/serve |
| 与索引一致性 | 不改变嵌入算法本身 | **必须**与 ingest 时同一后端；`--offline` 索引不可与 SiliconFlow/Gemini/FastEmbed 索引混用 |

简记：

- **编译期**：`--no-default-features` = 不要本地 ONNX。
- **运行期**：`--offline` = 不要远程/本地模型，用确定性 hash。

Cargo 的 `--offline`（禁止从网络取 crates）与本 CLI 的 `--offline` 无关，勿混淆。

## 4. `serve`：端口、CORS、鉴权

### 4.1 绑定与端口

```text
--bind / -b   默认 127.0.0.1:3000
```

- 默认**仅本机**（ADR 0003）。局域网需显式：`--bind 0.0.0.0:<port>`，并建议配置 API token（ADR 0005）。
- 另有：`--index-file`、`--tantivy-dir`、`--graph-file`（默认 `data/graph_store.bin`）、LLM `--base-url` / `--api-key` / `--model`、`--no-rerank` / `--rerank-model`，以及与 ingest 一致的 `EmbedderArgs`（含 `--offline` 等）。

### 4.2 CORS 白名单（ADR 0004）

优先级：`--cors-origins` / `MAO_CORS_ORIGINS`（逗号分隔）→ `config.toml` `[server].cors_origins` → **localhost 默认**：

- `http://localhost:3000` / `http://127.0.0.1:3000`
- `http://localhost:5173` / `http://127.0.0.1:5173`
- `http://localhost:8080` / `http://127.0.0.1:8080`

允许方法：GET / POST / OPTIONS；常见头：`content-type`、`authorization`、`x-request-id`。无 `Origin` 的非浏览器客户端不受 CORS 限制。

### 4.3 Bearer 鉴权与 ask 并发（ADR 0005）

```text
--api-token / MAO_API_TOKEN / [server].api_token
--max-concurrent-asks / MAO_MAX_CONCURRENT_ASKS / [server].max_concurrent_asks
  （CLI/env 默认 32；仅当 CLI 仍为默认 32 时 config 可覆盖）
```

- **未配置 token**：鉴权关闭（本机开发默认开放）。
- **已配置 token**：受保护路由需 `Authorization: Bearer <token>`，否则 HTTP **401**。
- **即使开启 token 仍公开**：`/live`、`/api/v1/live`、`/health`、`/api/v1/health`、`/metrics`、`/api/v1/metrics`、`/api/v1/stats`。
- **受保护**：`/api/v1/search`、`/api/v1/ask`、`/api/v1/ask/stream`、`/api/v1/verify`、`/api/v1/citation/verify`，以及 MCP 的 `/mcp`、`/api/v1/mcp`（探针路径不含 MCP）。
- ask / ask-stream 超并发 → HTTP **429**。开启 API auth 后，Bearer 专用于 API token；LLM 密钥走请求体 `api_key` 或服务端配置。

示例：

```bash
export MAO_API_TOKEN=replace-me
export MAO_CORS_ORIGINS=http://intranet-app.local:5173
cargo run --no-default-features -- serve --offline --bind 0.0.0.0:8080
curl -H "Authorization: Bearer replace-me" \
  -H "Content-Type: application/json" \
  -d '{"query":"持久战","top_k":3,"mode":"hybrid"}' \
  http://127.0.0.1:8080/api/v1/search
```

## 5. 健康与指标端点

| 路径 | 用途 | HTTP 语义 |
|------|------|-----------|
| `GET /live`、`GET /api/v1/live` | **存活（liveness）**：进程是否起来 | 只要进程在，恒为 **200**；body 仍可带 `index_loaded` 等信息（ADR 0002） |
| `GET /health`、`GET /api/v1/health` | **就绪（readiness）**：能否服务检索 | `total_vectors == 0` → **503** `unavailable`；有向量 → **200** `ok`。Tantivy 仅信息字段，不单独决定状态码 |
| `GET /metrics` | Prometheus 文本指标 | 含 search/ask/mcp 计数与延迟、`mao_llm_fallback_total`、`mao_mcp_requests_total` 等 |
| `GET /api/v1/metrics` | 同上指标的 JSON | 便于程序消费 |
| `GET /api/v1/stats` | 向量库统计诊断 | 与 readiness 分离；不因空索引强制 503 |

编排建议：重启探针用 `/live`，摘流探针用 `/health`。

```bash
curl -sS http://127.0.0.1:3000/live
curl -sS -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/health   # 有索引时期望 200
curl -sS http://127.0.0.1:3000/metrics | head
```

主要业务路由（摘要）：`POST /api/v1/search`、`/api/v1/ask`、`/api/v1/ask/stream`（SSE：`retrieved → reranked → delta → citation → done`）、`/api/v1/verify`（别名 `/api/v1/citation/verify`）、`POST /mcp` 与 `/api/v1/mcp`。

## 6. 常见故障排查清单

1. **`/health` 返回 503**  
   - 未 ingest 或 `vector_store.bin` 未加载成功（`total_vectors == 0`）。先 `init-samples` + `ingest`，确认 `serve` 日志中 vector index loaded。

2. **向量模型 / 维度不匹配**  
   - CLI 会提示 snapshot 与当前 embedder 的 model/dim 不一致。ingest 与 search/ask/serve 必须同一后端（例如全程 `--offline`，或全程 SiliconFlow）。混用需重建索引。

3. **`--no-default-features` 构建后无密钥启动失败**  
   - 预期行为：无 `local-embed` 时必须 `--offline` 或提供 SiliconFlow/Gemini/Cohere 密钥。不要指望静默 hash 回退。

4. **CORS 浏览器报错**  
   - 把前端 Origin 加入 `--cors-origins` / `MAO_CORS_ORIGINS` / `[server].cors_origins`。默认只放行上述 localhost 端口。

5. **401 unauthorized**  
   - 已设置 `MAO_API_TOKEN` / `--api-token` 却未带 `Authorization: Bearer …`。探针路径无需 token；search/ask/MCP 需要。

6. **429 on ask**  
   - 超过 `--max-concurrent-asks`（默认 32）。降低并发或调高限额；SSE 在整段流期间占用许可。

7. **Rerank 未生效**  
   - `--offline`、`--no-rerank` 或无 Cohere/`EMBED_API_KEY`/`[cohere].api_key` 时跳过精排，保留 RRF 融合顺序。

8. **图谱无效果**  
   - 缺少 `data/graph_store.bin` 时为 no-op。需先 `scripts/build_knowledge_graph.py` 再 `ingest-graph`；仅 hybrid 模式会扩展候选。

9. **SiliconFlow HTTP 429**  
   - 减小 `--batch-size`（16~32），依赖 CLI 批次间隔；检查免费额度约 2000 RPM / 500k TPM。

10. **编译失败（edition 2024 / 链接器）**  
    - 升级 rustup stable；安装 `build-essential`、`pkg-config`。服务器发布优先 `cargo build --release --no-default-features`。

11. **配置未加载**  
    - 确认 cwd 下有 `config.toml`，或设置 `MAO_AGENT_CONFIG`。解析失败会 warn 并当作未配置。

12. **优雅退出**  
    - Ctrl+C / SIGTERM 触发 graceful drain（见 runbook）；编排时给足停止宽限时间。
