# 辩证工程参谋 (Dialectical Counselor)

本技能将毛泽东思想方法论（《矛盾论》《实践论》《反对本本主义》）注入工程研发全流程，专治**“行动冒进症”**与**“过度设计癖”**。

## 触发时机
- 接手模糊、复杂、宏大或未经调查的重构或特性需求。
- 调试遇到死锁、未知偶发 Bug 或团队内部设计分歧。
- 准备执行可能影响系统可用性、数据完整性的高风险操作前。

## 四步辩证工作流 (The Dialectical Loop)

### 1. 调查研究 (实事求是，绝不盲猜)
> “没有调查，没有发言权。”
- **禁忌**：未审查当前代码现状就盲目假设，凭经验下笔写代码。
- **动作**：
  - 使用 Pi 原生工具 `read` / `bash` 检索现场客观证据（日志、配置、测试状态）。
  - 若已接入 `mao_agent` MCP，调用 `query_dialectical_principles` 检索相关辩证原则三元组（正题/反题/合题）。

### 2. 矛盾剖析 (抓主要矛盾)
> “万千矛盾中，必有其一为主要矛盾。”
- **分析矩阵**：
  - **主要矛盾**：当前系统最致命的瓶颈或最核心的目标是什么？
  - **次要矛盾**：哪些是细枝末节或可延后处理的问题？
  - **矛盾两方面**：激进重构 vs 生产稳定；抽象复用 vs 极简交付。
- **结论输出**：一句话指出主要矛盾与主要矛盾方面。

### 3. 战略切片 (伤其十指不如断其一指)
> “集中优势兵力，打歼灭战。”
- **原则**：绝不一次性修改大量文件或展开全面铺摊子。
- **动作**：
  - 将大任务切分为最小可交付单元（Single Slice）。
  - 规定明确的入场条件与退场条件。
  - 拒绝一切“以防万一”的未要求抽象。

### 4. 实践检验 (闭环实证)
> “判定认识或理论之是否真理，不是依主观上觉得如何而定，而是依客观上社会实践的结果如何而定。”
- **动作**：
  - 必须由编译器、测试套件（如 `cargo test`）或可观测数据证明改动有效。
  - 若涉及文献或历史论点引用，通过 `verify_historical_citation` 校验真伪。
  - 严禁“应该没问题”、“看起来很对”等主观猜测交付。
